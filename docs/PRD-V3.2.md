## 3. 身体指标与计划权限分离

建立统一的基础指标计算层与健康适用性/方案生成权限层。基础指标有效时，即使用户不适合自动配餐，也可显示 BMI 等有效估算，并标注估算限制；不得因不适合减脂而隐藏全部身体指标，也不得把基础指标可计算误认为适合生成饮食方案。

输入包括性别、年龄、身高、最新实际体重、用于计算的趋势体重、目标体重、日常活动量、体重管理目标、调整速度、健康筛查、过敏及忌口、近期体重变化。校验有限数值、单位、有效日期及应用适用范围。未成年、孕哺期、进食障碍风险、特殊疾病/医嘱等沿用并复核原有安全保护。超出原通用模型适用范围（例如 BMI≥40、年龄超出范围）提示专业评估，而不是套用普通自动配餐。

体重或健康信息缺失时显示待填写，不以 0 或其他档案数据代替。

## 4. 统一 BMR、TDEE 与 BMI 计算

采用现有 Mifflin–St Jeor 静息能量消耗估算公式，明确 BMR 为应用展示名称、TDEE 为估算而非实测。

```ts
const bmi = calculationWeight / (heightCm / 100) ** 2;
const actualBmi = currentWeight / (heightCm / 100) ** 2;
const bmr = 10 * calculationWeight + 6.25 * heightCm - 5 * age
  + (sex === '男' ? 5 : -161);
const tdee = bmr * activityFactor;
```

保留现有活动系数映射：长期久坐 1.2，正常通勤 1.375，经常站立走动 1.55，体力劳动 1.725。明确这些是应用经验估算参数。活动量已包含运动时不得重复加算运动消耗。

不同身体数据必须得到独立计算结果；计算保留必要精度，显示时统一四舍五入，不根据显示后的 BMI 再判断临界值。

## 5. 完整 BMI 区间及目标模式

采用中国成年人 BMI 分类：低于 18.5 为低体重，18.5 至不足 24 为正常体重，24 至不足 28 为超重，28 及以上为肥胖范围。BMI 是分类和筛查依据，不是疾病诊断或唯一减重/增重依据。

| BMI | 默认建议与适用限制 |
|---|---|
| <16 | 明显低体重，优先专业营养评估，不自动生成普通增重或减脂食谱 |
| 16～不足18.5 | 低体重，先进行营养及再喂养风险筛查；符合条件才提供健康增重；禁止减脂 |
| 18.5～不足24 | 默认维持；有合理需求且符合条件可选择健康增重或适度减脂 |
| 24～不足28 | 根据目标和健康情况推荐温和减脂或维持 |
| 28～不足40 | 根据健康情况进行合理减脂或维持，限制最大缺口 |
| ≥40 | 超出当前通用方案范围，提示专业评估 |

以上为应用策略建议，开发时核对可靠的成人体重管理及临床营养指南，不得把产品策略冒充临床诊断标准。BMI 18.5 是分类下限而非推荐减脂目标；接近低体重时可根据健康风险提前停止减脂。低体重不能无限增热量。增重不等同于增肌，不宣传治疗疾病。

个人档案目标增加“健康增重”，与“减脂”“维持体重”并列。区分用户期望目标、实际执行模式、可生成权限及原因。切换目标时检查目标体重方向、BMI 及适用性；不擅自重置用户历史偏好。无合理目标时不强制进行增减重。若目标已达到或越过，按方向停止调整，不自动反向增减重。

## 6. 统一减脂百分比曲线（取代旧固定缺口）

系统推荐采用 TDEE 百分比模型，以下控制点沿用最新 V3.2 讨论：

| BMI | 缓慢减脂候选缺口占 TDEE | 适中减脂候选缺口占 TDEE |
|---|---:|---:|
| ≤18.5 | 0% | 0% |
| 19 | 0.91% | 1.09% |
| 20 | 2.73% | 3.27% |
| 21 | 4.55% | 5.45% |
| 22 | 6.36% | 7.64% |
| 23 | 8.18% | 9.82% |
| 24 | 10% | 12% |
| 25 | 10.625% | 12.75% |
| 26 | 11.25% | 13.5% |
| 27 | 11.875% | 14.25% |
| ≥28（适用范围内） | 12.5% | 15% |

在 18.5、24、28 三个控制点之间线性插值，28 以上不无限扩大比例。该曲线仅为候选缺口，必须通过后续健康安全校验。

```ts
function bmiDeficitRate(bmi: number, pace: '缓慢' | '适中'): number {
  if (!Number.isFinite(bmi) || bmi <= 0) throw new Error('无效BMI');
  const normalRate = pace === '缓慢' ? 0.10 : 0.12;
  const upperRate = pace === '缓慢' ? 0.125 : 0.15;
  if (bmi <= 18.5) return 0;
  if (bmi < 24) return normalRate * (bmi - 18.5) / 5.5;
  if (bmi < 28) return normalRate + (upperRate - normalRate) * (bmi - 24) / 4;
  return upperRate;
}
```

同一 BMI、同一速度得到同一候选比例；不同 TDEE 得到不同候选绝对缺口。删除旧 `autoRamp`、与其相关的 `transitionCap` 及重复乘用 `bmiFactor` 的路径。不得在不同模块再次套用相同 BMI 衰减。

这些比例是产品配置提案而非临床验证公式。开发前核对可靠指南，若需调整参数以满足安全要求，应记录理由、原始依据和新旧结果，不得静默增加第二层相同 BMI 衰减。

## 7. 健康增重独立模型（BMI 18.5 以下及适用的正常 BMI）

低体重用户应有独立的增重路径，而不是直接报错、照搬减脂曲线或自动无限加热量。增重必须先评估营养状况、非自主体重下降、长期进食不足、进食障碍、用药及其他健康风险。

支持系统推荐、缓慢增重、适中增重、自定义热量盈余。可将 TDEE 的 10%（缓慢）、15%（适中）作为候选产品配置参考，开发时核对可靠营养指南，明确适用人群、合理上限及调整规则。不要把候选百分比当成每个人必然可以使用的处方。增重模型独立于减脂模型；不直接将减脂曲线反转。

此前讨论未确定低体重各 BMI 点的具体盈余百分比，因此本次不得把未经验证的低 BMI → 更高盈余曲线写成临床事实。可在适用的低体重区间采用经过说明且有上限的连续候选策略，或采用上述温和基础比例，并依据距目标和体重趋势连续收窄。任何额外 BMI 调节只执行一次，配置及依据必须写入文档。较低 BMI 意味着更需要评估，不意味着自动提高盈余。

BMI<16 或存在严重营养不良、明显非自主体重下降、长期进食不足、再喂养风险等情况，停止普通自动增重方案并提示专业评估；16～18.5 也必须筛查，不能仅凭 BMI 或用户勾选确认放行。筛查不足则展示待评估，不擅自给出确定增重热量。

增重时目标体重应高于当前体重，并通过目标合理性评估。逐步接近目标时缩小盈余；达到或超过目标时归零。BMI 恢复至 18.5 后，尚未达到合理增重目标且仍符合健康条件时可以继续增重，不因跨过 18.5 自动取消全部盈余。正常 BMI 用户如有合理增重需求也应走同一安全流程。

## 8. 双向统一能量引擎与安全修正

统一符号：正值代表盈余、负值代表缺口、0 代表维持。所有模式调用同一个能量引擎，不建立彼此矛盾的首页、预览和配餐计算公式。

```ts
// 示意：各 cap 都由独立校验函数提供，非固定医疗处方。
const candidateDeficit = tdee * bmiDeficitRate(bmi, pace);
const remainingLossKg = Math.max(0, Math.min(currentWeight, calculationWeight) - targetWeight);
const distanceCap = remainingLossKg * 300; // 沿用原距离衰减配置，可有依据地调整
const energyCap = Math.max(0, tdee - minimumEnergy);
const actualDeficit = Math.max(0, Math.min(candidateDeficit, distanceCap, energyCap, safetyCap));
// 增重路径使用独立的候选盈余与目标距离、趋势、营养适用上限。
// 未通过健康筛查时停止自动方案，不以任意 cap 代替评估。
const adjustment = mode === '减脂' ? -actualDeficit : mode === '健康增重' ? actualSurplus : 0;
const dailyKcal = Math.round(tdee + adjustment);
```

实现时明确 `actualSurplus` 的来源、配置上限与安全校验；按增重方向计算剩余距离，最新体重或趋势体重已达到目标则优先停止盈余。距目标限制连续收窄，不必机械套用减脂的距离常数。最终调整不能小于/大于适用方向的安全上限。

保留原有最低能量、体重下降过快、异常称重、年龄及疾病筛查等保护，并核对适用性；原男性 1500、女性 1200 千卡是应用配置保护值，不是个人处方，也不是营养充足性的唯一保证。若 TDEE、目标或营养需求超出通用模型，不强行钳制成看似正常数字继续生成。保留 65 岁起等原有保守规则，增重是否适用独立评估，不能默默绕过年龄保护。

安全层应给出结构化状态（可生成/需核对/需专业评估）、原因、候选比例、候选调整量、实际调整量及相关限制。安全层可以停止或收窄，但不能重复执行 BMI 衰减。实际缺口不一定随 BMI 单调变化，最终热量也不必随体重单调升降。

## 9. 自主热量模式与旧设置兼容

保留并统一：系统推荐、维持体重、缓慢减脂、适中减脂、缓慢增重、适中增重、自定义（依据所选目标提供相应方向）。自定义支持百分比以及兼容旧的千卡数值。

系统推荐从档案目标、速度、健康适用条件决定比例；维持体重的调整量为 0。减脂自定义候选可取用户所选百分比或千卡值，再受适中曲线对应 TDEE 上限、目标距离、健康及最低能量限制；不得再乘旧 BMI 系数。原自定义 0～400 千卡范围在迁移中保留，若未来调整范围须明确说明。增重自定义使用独立盈余上限，不允许无界数值。校验 NaN、Infinity、负值、空输入、超出范围及调整方向冲突。

界面区分“选择的标准值”和“最终实际允许的调整量”。旧版明确选择固定 300/400 千卡的用户不得无提示改变意愿；迁移时展示新旧计算差异，必要时让用户确认使用新百分比曲线或保留为受新版安全上限约束的自定义设置。旧维持模式保持维持，不自动切换增减重。保存失败不能显示已保存。

## 10. 正常 BMI 适用性与模式切换

正常 BMI 默认维持，但已选择减脂/增重、具有合理需求且符合条件的用户可以使用适当的动态调整。正常 BMI 减脂确认与具体模式分别保存，系统推荐也可读取有效确认，而不是只让手动模式生效。

从 BMI 24 以上进入正常范围时，已确认且仍适用者继续按同一候选曲线计算；未确认或有风险者明确提示评估，必要时停止调整。不因跨区间无提示清零保存偏好，不重新引入 BMI 24～25 隐藏斜坡。由低体重恢复至正常范围时同样依据合理增重目标及安全情况判断，不强制反向减脂。

审查 `normalOptIn`、`normalEligible`、`stopped` 及旧 `conditions.length` 一刀切条件，区分普通注意事项与确需医学评估的情况，不擅自将任何疾病列为可自行减脂/增重。健康资料或用药变化时重新评估确认是否仍有效；不能以用户自行勾选替代必要专业评估。安全停止优先于曲线连续性。

## 11. 体重趋势、阶段及双向进度

最新实际体重用于首页和必要安全校验；有效趋势体重用于能量估算，记录不足时用最近有效称重或档案备用体重，不编造数据。保留现有近 7 日样本、此前窗口及异常变动规则并复核日期口径与适用性。体重快速变化时先提示核对/评估，不能机械增加缺口或盈余。

记录、编辑、删除体重，或修改身高、年龄、性别、活动量、目标、健康情况时重新计算。起始体重、起始日期、最新体重、目标体重和历次记录独立保存。仅用户主动确认开启新阶段才重设起点。

减脂进度：累计减重 = 起始体重 − 当前体重；目标方向距离 = 当前体重 − 目标体重；百分比按已完成变化/目标变化计算。

增重进度：累计增重 = 当前体重 − 起始体重；目标方向距离 = 目标体重 − 当前体重；百分比采用对应增重方向。

维持模式展示当前体重、趋势及与参考体重的偏差，不显示虚假的减重进度。进度条可限制在 0～100%，真实反弹、反向变化、超过目标的数字不得隐藏或篡改。起始等于目标时避免除零。允许阶段切换并保留此前称重历史。

验证未来日期、同日重复记录、编辑日期、删除最新记录、时区/跨日、记录不足、相同体重、异常输入及趋势图边界。不得伪造历史称重日期。

## 12. 首页热量卡、计算依据与统一展示

沿用 V3.0 卡片设计。首页展示当前档案名称、实际管理模式、每日建议热量、实际缺口或盈余；提供设置热量入口。详细计算依据默认折叠，必要时显示调整原因和适用性提示。

详情至少包括：最新体重、计算体重及选择依据、实际与趋势 BMI、BMR、活动系数、TDEE、用户期望目标/速度、候选调整百分比、候选调整量、距目标限制、健康及营养修正、实际调整量、最终摄入目标、算法版本、计算日期、变化原因。明确估算而非实测；不适合生成时不能仍显示正常的减脂或增重计划。

“减脂”但实际缺口接近 0、“增重”但实际盈余接近 0 时应说明原因。保持候选调整和实际执行模式一致，不为显示漂亮数字掩盖安全限制。设置预览、首页、生成设置、Worker、实际配餐调用同一函数和同一档案快照；保存后立即同步并在刷新后恢复。

## 13. 食谱与营养双向支持

减脂、维持、健康增重均需真实生成与当前目标匹配的食谱，不只改首页显示值。重新评估蛋白质、脂肪、碳水、膳食纤维、钠及已有微量营养指标；营养数据缺失不能作 0。增重通过合理增加营养丰富的食材及餐次实现，优先优质蛋白、谷物薯类、奶豆、坚果种子、适量油脂、蔬菜水果。不得主要依赖大量油、糖、高盐食品、甜饮料来凑热量。营养算法需要结合实际可行性，不因热量达标而牺牲其他必要营养。

继续遵守过敏、忌口、厨具、库存优先、集中采购、固定水果/早餐、锁定食材及采购批次等约束。不适合通用配餐或无法满足条件时明确原因，不伪造成功结果。

区分当前建议热量、当前方案生成时目标、计划摄入及已记录实际摄入。新旧目标不同时明确提示并提供更新未执行食谱入口。普通体重更新不应无故清空手动锁定或阻断所有操作；重大健康变化需重新校验。历史方案、已执行餐次、实际购买、付款及库存流水保留原始快照，不能被新版算法回溯改写。

## 14. 多档案数据架构

原 `store.ts` 仅支持单个 Data 对象。升级为有稳定档案 ID 的多档案架构，将公共设置与档案数据分离。每个档案使用 UUID，不以姓名、数组下标或当前选中位置作为唯一标识。参考结构如下，可根据实际 IndexedDB 设计调整：

```ts
type ProfileEntry = {
  id: string;
  name: string;
  createdAt: string;
  updatedAt: string;
  revision: number;
  data: ProfileData;
};
type AppData = {
  schemaVersion: number;
  activeProfileId: string | null;
  profiles: ProfileEntry[];
  settings: AppSettings;
};
```

可使用独立 object store 或按 ID 分区保存；优先实现原子事务、版本校验、迁移安全和可靠并发，不强制使用示例中的具体存储布局。沿用本地 IndexedDB，不增加账号依赖、云端同步或未经授权上传健康数据。档案名称可重复但 ID 不可重复。所有用户数据操作须显式区分应用级与档案级范围。

## 15. 档案隔离范围与公共资源

每个档案必须独立保存：

- 个人身体信息、健康筛查、过敏、忌口及其他健康资料。
- 起始体重、阶段、目标体重、历次称重、实际体重和进度。
- 体重管理目标（减脂/维持/健康增重）、速度、热量设置、适用性确认及必要算法记录。
- 厨具、饮食偏好、餐次、固定早餐、固定水果、必选菜。
- 当前食谱、历史食谱及生成时营养目标快照。
- 食材锁定、优先、排除、严格食材池、模板、菜谱收藏及屏蔽。
- 采购次数、日期、备餐周期、人数、预算、当前采购需求。
- 家中库存、库存流水、购买记录、付款记录、库存调整、清空及撤销记录。
- 自定义价格、包装规格、重量与体积换算配置。
- 实际执行、取用、制作、分装和用餐记录。

公共数据包括基础食材及菜谱数据库、基础分类、公共默认参考价格、应用版本、主题和全局设置。自定义价格不与公共参考价格混淆。

默认库存和采购账本按档案独立，不在本次实现家庭共享库存。创建 B 档案不能自动继承 A 的健康数据、库存、采购或食谱。此隔离策略必须在档案管理页面简洁说明，避免用户误以为多个档案共享真实厨房库存。

## 16. 新建、编辑与档案切换

在“我的”页面提供档案管理入口；顶部头像支持打开档案切换面板。支持多个档案，不人为限制为两个；测试至少创建 5 个。档案命名、重命名、编辑、新建均使用稳定 ID；允许同名。新建进入现有档案填写流程，从独立初始状态开始。可保存尚未填写完成的档案，但不得绕过生成前必需资料及健康筛查。

档案选择面板显示名称、当前体重、目标体重（如适用）、管理目标及当前使用状态，并提供切换、编辑及独立删除入口。缺失资料显示未填写，不显示虚构数值。

切换流程：

1. 保存当前档案已确认的修改，未保存表单提示保存或放弃。
2. 安全处理正在进行的生成、保存、库存及其他异步操作。
3. 读取目标档案最新持久化数据及修订版本，重新计算其热量及采购库存派生结果。
4. 清理上一个档案的页面临时状态、弹窗、选择项、历史查看状态及临时缓存；返回首页。
5. 持久化最近使用档案 ID，刷新或重新打开应用恢复该档案。

所有页面应显示目标档案正确的数据。切换后不能沿用上一个人的 BMI、年龄、活动量、目标方向、热量缺口、库存、菜谱或价格。不要把档案切换做成仅改变名称的 UI 操作。

## 17. 独立删除档案与清空功能

每个档案提供单独删除。确认对话框展示明确档案名称、必要区分信息、将删除的数据范围及不可逆后果；允许先导出该档案备份。二次确认后仅删除指定档案及关联数据，并原子更新当前档案指针。

删除非当前档案时不改变当前档案。删除当前档案时自动选择其他可用档案并提示；删除最后一个时进入新建档案空状态。不能白屏、崩溃、自动恢复已删除数据或清除公共数据库和主题。

单档案删除、删除称重记录、删除历史方案、库存单项清空、库存全部清空、删除本机全部档案是不同操作，明确范围。库存清空及撤销只作用于当前档案，保留相应购买流水、付款与历史方案。全局删除全部数据须明确影响所有档案并进行二次确认，不与普通删除按钮混放。

## 18. 旧版数据无损迁移

首次打开 V3.2 时，将既有完整单档案 Data 迁移为首个档案。保留旧档案名称、身体数据、体重阶段、称重历史、热量设置、当前及历史食谱、库存、全部流水及付款、备餐执行、锁定、偏好、价格、包装、采购设置和其他已有数据。不得只迁移个人资料而丢失关联数据。若旧库没有 profile 但仍有其他用户数据，应保留为待补档案或明确恢复状态，不能无条件初始化覆盖。

采用原子迁移，校验成功前保留原数据。迁移幂等：刷新、重复启动、多个标签页同时打开不会创建重复档案。迁移失败回滚，显示原因与恢复路径，不自动清空。更新存储 Schema、版本号、Zod 校验、旧版兼容及备份格式。不要把原有记录的日期或历史营养目标改为新值。旧食谱保留原算法快照，当前新建议单独计算并提示差异。

旧版本的固定千卡设置按第 9 节处理。升级前后对比数据记录数、关键字段、库存余额、购买金额及历史快照。明确迁移的版本和测试结果。

## 19. 单档案和全档案备份恢复

提供导出当前档案、导出全部档案。支持读取旧单档案备份、新单档案备份和新版全部档案备份，包含数据/算法版本及必要引用。

导入单档案默认新建独立档案；只有用户明确指定并确认才覆盖目标档案。导入全档案允许明确选择合并或替换全部。显示导入影响范围，校验结构、文件大小、日期、ID、外键和数据一致性。重复 ID 应明确跳过、作为独立副本或覆盖的策略，避免重复导入把购买流水合并两次或库存累加两次。

导入失败不得部分覆盖有效数据。备份包含健康信息，保留隐私提醒。不上传至外部服务，不要求注册账号。保留价格等已有专项备份能力，并绑定正确档案。

## 20. 防止异步任务与多标签页串档

重点检查 `mutate`、`queuePreferenceWrite`、`generate`、`cancelGeneration`、`loadData`、`writeData`、Web Worker、BroadcastChannel、库存/采购/称重保存、备份恢复以及历史方案操作。

每次写入、异步生成、回调和消息在发起时绑定 profileId 与必要 revision/taskId。完成时校验档案仍存在且版本有效；不得临时读取新的 activeProfileId 作为写入目标。A 档案生成期间切换到 B，A 的结果不能覆盖 B，也不能在 B 页面显示 A 的成功或失败结果。可取消旧任务或仅向原档案写回并严格校验；切换、删除后安全忽略过期回调。

删除档案后，旧任务、缓存和标签页消息不能重新创建被删除的档案。并发修改需检测版本冲突并给出重试或重载反馈，避免旧快照整体覆盖别人的更新。活动档案指针与数据写入的事务范围明确。所有派生缓存、React 状态、搜索、替换面板、表单及历史选择按档案隔离或切换时重置。

## 21. UI 与移动端交互要求

保留 V3.0 品牌绿色、统一图标、列表、底部弹层及确认对话框。首页、食谱、采购、我的四项底部导航保持不变。

我的页面顶部显示当前档案卡片，提供新建、切换、编辑、管理入口。顶部头像可打开切换面板。当前档案名称在重要操作处清晰显示，防止误操作其他档案。删除入口与普通切换分离，明确当前选中状态。热量设置沿用现有入口，不额外增加多个重复设置页面；按目标展示缺口或盈余设置。

适配 320/360/375/390/430px 手机、平板、桌面、安卓 Chrome 与 iPhone Safari/PWA。保留浅色、深色、跟随系统；检查安全区域、键盘、滚动、返回、弹窗焦点、触控、长名称、字体放大及空状态。不得因新增档案造成原页面拥挤或数据布局退化。

## 22. 保留并回归 V3.1 全站业务一致性

本次不是重新开发所有稳定模块，但须确保双向热量和多档案不会破坏此前功能。以下均按当前档案校验：

- 采购：同一商品在不同批次的项目数与去重商品种类分开统计；首页、全周、各批次共享状态函数，库存覆盖不当作未购。价格未知、重量换算待核对、购买数量不足和实付未知是不同状态。采购次数不得擅自增加。
- 费用：实际支付、已购未填实付估算、剩余预计采购、预计总费用、消耗价值及预算分开；未知不是 0，历史实际支付不能被当前价格覆盖。
- 库存：所有采购真实入库、取用真实扣减、不重复扣减；同日多次购买、追加、修正、撤销、单项清空、全部清空及撤销正确；清空后无库存复活；库存长期保存，不按有效期自动失效。库存记录与实际食品是否适合食用是不同概念，保留原有必要食品安全提示。
- 采购去重：自制生熟状态折算至真实采购原材料 ID；不同商品不能仅因用途类似而合并真实库存。常备调味料与主要食材分开；保持全品类合理替换与集中采购。
- 备餐：待取用、已取用、已制作、分装及用餐分别计数；不能重复扣库存。采购和备餐日期按各自计划，不混淆。
- 营养：按最终份量计算能量、宏量及已有微量营养；生熟、毛净、干重和液体密度换算正确。复合调味料使用真实营养数据，缺失不作零。多人采购乘人数，每人营养目标不翻倍，历史已执行用量不被新人数改变。
- 计划与实际：生成食谱不提前扣真实库存；计划摄入、取用、真实食用分别记录，无法确认实际食量时不冒充实际摄入。
- 食材偏好：多食材锁定、四状态偏好、严格食材池、固定早餐/水果、替换选择器均正常。不能旧设置覆盖新设置；替换相同水果不能只换菜名。
- 分类大全：保留食谱大全、原材料大全、搜索、分类、营养来源、价格与库存联动；基础数据库共用，档案偏好及用户设置独立。
- 日期及历史：今天、明天、下周一、自定义日期、跨月跨年正确；过去食谱不冒充今日食谱，历史仅显示自己的快照和执行记录。
- 边界值：避免 NaN、Infinity、负库存、负采购量、除零、空字符串变 0、未知金额变 0、精度汇总误差及重复流水。显示统一格式化，从原始精确数据汇总。

保留离线使用、PWA 更新、现有数据保护及备份。禁止重新引入烹饪时间限制或库存有效期管理。已确认存在的业务问题添加复现及回归测试，未复现风险如实记录。

## 23. 全身体数据参数化测试

不得只测试用户 173cm、72kg 的案例。建立参数化测试矩阵：

- 性别：男、女。
- 身高：145、150、160、173、180、190、200 cm；补充应用合法范围端点及非法输入。
- 年龄：18、25、35、45、60、65、79 岁；补充未成年人和超范围输入。
- 活动量：全部 4 个活动系数。
- BMI：14、15、15.99、16、17、18、18.49、18.5、18.51、19、20、21、22、23、23.99、24、24.01、25、26、27、27.99、28、28.01、30、35、39.99、40 及以上。
- 目标：减脂、维持、健康增重；目标未达到、接近、等于、超过及方向冲突；健康适用性确认、有无风险、数据缺失及异常趋势。
- 速度与模式：自动、缓慢、适中、自定义百分比、旧自定义千卡，包含 0、负值、无效值、边界值及超出上限。

根据 BMI 和身高动态生成测试体重：`weight = bmi * (heightCm / 100) ** 2`。不能为不同身高固定同一个体重区间。覆盖数百组以上不同档案及边界组合，不适用组合应正确阻止自动方案，而不是强制返回热量计划。

独立校验 BMR/TDEE、候选比例和实际调整量，候选比例在控制点连续、非递减且不超过配置上限。相同 BMI/速度对应相同比例，不同 TDEE 得到不同候选千卡。实际缺口及最终摄入量受健康、目标、趋势限制，不强求单调。有效结果必须有限、方向正确，安全保护不被绕过。

增重验证：低体重禁止减脂；符合条件的增重用户得到经评估的合理正向盈余；严重低体重、再喂养或其他高风险正确拦截；接近目标逐渐收窄，达到/超过目标盈余归零；跨过 18.5 时若仍适用且未达到目标，不突然取消盈余。增重、减脂和维持的进度方向及食谱营养均正确。

## 25. 多档案测试验收

至少创建 5 个档案，覆盖不同目标及身体数据，包括 A 减脂、B 健康增重、C 维持。逐项验证：

4. A 的采购、库存、价格、包装规格、购买及实付记录不串用。
