# 天天减 V3.0 界面设计系统

## 改版前检查

用真实 Chromium 在 390×844 CSS 像素下打开 V2.4.1 与 V3.0 生产构建。两个版本使用相同的虚构档案、体重序列、真实算法生成的食谱、库存和收藏方案。浅色、深色各采集 17 个页面与交互状态。旧版清空库存的截图记录了触发原生确认前的页面。

| 改版前实测 | 新版处理 |
| --- | --- |
| 首页体重、目标和营养值挤在同一行，趋势需要展开 | 体重作为主卡片的关键数字，真实数据曲线独立呈现，任务区按今天、采购和备餐组织 |
| 生成和换菜操作与任务并列，菜谱详情展开后整餐被拉长 | 日期条区分执行状态。菜品紧凑列表、菜谱详情和替换候选分层 |
| 采购批次和分组层次相近，购买编辑插入长列表 | 顶部实付、剩余、进度与费用明细分层，批次保留进度。实际购买登记使用弹层 |
| 备餐步骤与食材、调味料混排，执行进度不易扫读 | 批次分别显示取用、制作、分装，内部按真实任务组织 |
| 两个大全把分类、筛选和结果一起显示，详情留在主列表 | 食谱按类别网格浏览。原材料第一级为带彩色插画的分隔列表，下一级是二级分类和分页结果，详情单独打开 |
| 个人中心和历史入口较分散，库存流水及编辑随行展开 | 我的按功能分组，历史次要操作收纳，库存增减和流水集中到商品详情 |
| 生成设置较长，手机操作时需要反复回到生成按钮 | 五个模块，低跨层操作。筛选内批量选择共用四种食材状态和原持久化路径 |

## 令牌和组件

- 底色、卡片、文字、边框、品牌、状态及反差色均从 `src/style.css` 的浅色及深色令牌取值。浅色页面 `#F6F8F5`，卡片 `#FFFFFF`，正文 `#17251E`，品牌 `#245A43`。深色采用独立的墨绿背景和浅色正文。
- 间距以 4 CSS 像素为基础，常用内边距为 12～24 像素。主要卡片圆角 18 像素，按钮 12 像素。可读字号使用相对单位，主要控制最小触控尺寸为 44 像素。
- `src/design.tsx` 集中管理本地线性 SVG、食材分类插画、标题、操作、列表行、搜索、分段选择、状态、进度和弹层。空状态、营养指标和编号菜谱步骤由 `src/ui.tsx` 复用。页面保留系统中文字体。
- 档案、食谱和费用均使用原有数据结构。日计划中的热量以食谱用量计算，完成与取用单独记录。未知营养与未知价格继续沿用原校验和标注。

## 导航、键盘和弹层

四项主导航保持原有路径。二级页面使用顶部返回箭头，浏览器历史首先退回当前弹层或分类。大全保留上次筛选和分页，同一路由返回时恢复滚动。主要操作弹层使用原生模态容器、键盘焦点循环、Esc、关闭键和滚动隔离。危险操作明确标注并保留确认。应用底栏与弹层采用系统安全区域，动效遵从系统减少动态效果设置。

## 截图复现

完成生产构建后执行 `node --import tsx scripts/capture-ui.ts dist <截图目录> after`。对 V2.4.1 构建传入其 `dist` 并使用 `before`。追加 `webkit` 可使用 WebKit 和 iPhone 13 设备配置。截图仅使用虚构数据。测试范围、数量和性能记录见 [测试与验收](TESTING.md)。

## 对比度抽检

按 WCAG 的相对亮度公式抽检。浅色主正文与页面背景为 14.90:1，次要文字在卡片与浅绿底色上分别为 6.08:1 和 5.32:1，主操作文字为 8.02:1。深色卡片中的主正文为 14.03:1，次要文字为 8.43:1，危险状态文字与背景为 7.24:1。
