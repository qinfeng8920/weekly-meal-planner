# 天天减 V1.0 — Codex 完整开发指令

## 一、开发者身份及我的情况

你是一名资深全栈开发工程师、产品经理、UI设计师和软件测试工程师。

我是没有编程基础的普通用户，目前只有安卓手机，没有电脑，通过 ChatGPT 手机客户端中的 Codex Cloud 与你沟通。请尽可能在云端完成实际开发、测试及部署，不要求我安装电脑软件、使用本地终端或手动编写代码。涉及 GitHub 连接、仓库授权、云端环境、合并或部署时，请提供适合手机的逐步操作说明。不要声称拥有尚未获得的权限。

## 二、项目目标

开发名为「天天减」的个性化减脂饮食管理 App，英文项目名 `tiantianjian`，初始版本 V1.0。

采用 PWA 手机网页应用，最终获得一个可访问的网址。用户输入身体数据、健康注意事项、饮食偏好、厨房条件等资料后，自动计算营养需求，随机生成符合个人情况的七天食谱、采购清单、制作教程和集中备餐计划。支持每周更新体重、重新生成食谱、保存历史方案。

网址可分享给朋友，无须注册、无须 ChatGPT 账号即可独立使用，每个人的数据互不干扰。

## 三、技术架构

推荐 React + TypeScript + Vite，IndexedDB 本地数据库，PWA Manifest 和 Service Worker，GitHub 代码仓库，GitHub Actions 自动构建、测试，GitHub Pages 静态托管。如果更简单可靠的技术方案更适合云端和纯手机工作流，可说明理由后采用。

- 第一版不需要服务器、购买域名、付费 API 或大语言模型 API。
- 无须登录；支持安卓、iPhone 和桌面浏览器；支持添加到主屏幕，首次成功加载及缓存后核心功能可离线使用。
- 个人健康数据仅在用户本地处理，不使用广告、跟踪或不必要的统计服务。
- 尽量避免外部 CDN、外链字体等运行时依赖，考虑中国大陆访问条件。
- 预留微信小程序移植和云端同步扩展；核心算法不得依赖浏览器 UI，以便复用。

## 四、整体界面设计

全站简体中文，现代简约健康管理风格。低饱和森林绿、暖白底、深灰文字、圆角卡片、合理留白、明确数据层级，支持浅色与深色模式。移动端优先，兼容底部安全区域、不同屏幕和触控操作。不采用花哨渐变、过多阴影或复杂动画。所有交互按钮应有真实功能，具备加载、空状态、成功、错误及生成失败提示。

## 五、首次使用及个人档案

首次打开提供分步骤问卷，之后随时编辑。非必要信息可跳过，涉及安全筛查的必要信息不完整时不得生成可能不适用的减重计划。

### 1. 身体基本信息
- 昵称（选填）、性别、年龄、身高、当前体重、目标体重、腰围和体脂率（选填）。
- 减脂、维持体重等目标及预期减重速度。

### 2. 生活和运动
- 活动量：长期久坐、正常通勤、经常站立走动、体力劳动。
- 每周运动次数、类型、每次时长、起床及睡觉时间、三餐时间。

### 3. 健康及饮食限制
- 脂肪肝、高血糖、高血脂、高尿酸、高血压、痤疮、胃肠道问题、肾脏疾病、食物过敏及其他特殊情况。
- 明确询问是否未成年、孕期或哺乳期、存在进食障碍风险、医嘱特殊饮食或其他需要医学营养干预的情况。
- 健康标签仅用于一般饮食偏好、安全筛查和提示，不诊断疾病、不提供治疗方案。需要医学营养干预者停止通用自动减脂方案，建议咨询医生或营养师。

### 4. 饮食偏好
多选、自定义及屏蔽食材，区分强制限制与一般偏好。
- 菜系：中式家常、粤菜、川湘菜、日式、韩式、西式轻食、清淡、其他。
- 蛋白质：鸡胸肉、鸡腿肉、牛肉、猪肉、鱼肉、虾及海鲜、鸡蛋、豆腐及豆制品、牛奶、无糖酸奶。
- 主食：米饭、糙米杂粮饭、燕麦、红薯、土豆、玉米、面条、馒头、全麦面包。
- 蔬菜、水果、坚果、调味品可独立选择。
- 水果设置：正常摄入、优先低糖水果、自定义摄入量、不吃水果。不得将完整水果和添加糖、果汁等同，不得因脂肪肝默认禁止水果。
- 乳制品设置：正常摄入、减少牛奶、不吃乳制品、乳糖不耐受。

### 5. 厨房条件
- 煮锅、蒸锅、炒锅、电饭煲、微波炉、空气炸锅、烤箱、压力锅、冰箱、冷冻室、电子厨房秤。
- 厨艺：完全不会、简单做饭、熟练。
- 每餐可接受制作时间：10分钟以内、10～20分钟、20～40分钟、不限。

### 6. 采购及用餐条件
- 国家和城市、每周采购预算、用餐人数、采购次数、是否接受冷冻食材、是否接受重复菜、便当需求、午餐在家/食堂/外卖、现做或集中备餐、是否减少浪费、每日餐次数量。

## 六、首页

仪表盘展示日期、当前/初始/目标体重、累计减重、进度、BMI、估算 BMR、估算 TDEE、建议摄入热量、蛋白质/碳水/脂肪/纤维目标、建议饮水量（不适用于医嘱限水者）、近期体重曲线、今日食谱和采购进度。

快捷入口：更新体重、生成本周食谱、查看今日食谱、采购清单、历史方案。

## 七、营养计算引擎

独立、可维护、可单元测试的成人营养计算模块。Mifflin–St Jeor 公式（kg、cm、岁）：
- 男：BMR = 10 × 体重 + 6.25 × 身高 − 5 × 年龄 + 5。
- 女：BMR = 10 × 体重 + 6.25 × 身高 − 5 × 年龄 − 161。

根据日常活动量估算 TDEE，结合体重、目标、近期趋势设合理热量缺口；所有结果标明估算值。活动系数、缺口、最低摄入保护规则、适用范围及出处记录于营养规范，不能将 BMR 当成建议摄入量。

- 不鼓励快速减重、极端节食、默认戒碳水；优先营养均衡与肌肉保留。
- 正常体重用户避免不必要减重建议；低体重、不合理目标、未成年人、孕哺期、进食障碍风险、需要医学营养干预等情况停止通用自动减脂建议并提示专业评估。
- 体重变化不应机械导致摄入持续下降；依据最近2～4周趋势温和调整，短期波动不触发减量；到达目标可转维持饮食。
- 脂肪肝一般健康饮食偏好：减少添加糖、含糖饮料和酒精，允许适量完整水果，不宣称食谱治疗疾病。痤疮相关饮食建议须标注证据局限，不强制戒全部乳制品。
- 计算热量、蛋白质、碳水、脂肪、膳食纤维；有可靠数据时加入钠、钙、钾、维生素C等重点指标。
- 依据《中国居民膳食指南》及权威食物成分数据库等可靠资料，记录实际核验过的数据来源、版本、链接和单位。不编造引文或把未验证规则描述成医学结论。没有可靠数据的指标显示未知；必要数据缺失则不得将食谱标为合格。

## 八、食材数据库

独立结构化数据库，初期目标至少100种常见食材，可靠性优先。覆盖肉、鱼虾、蛋、豆制品、主食、蔬菜、水果、乳制品、坚果、植物油、常见调味料。

字段：唯一 ID、中文名及别名、分类、每100g热量/蛋白质/脂肪/碳水/纤维、可获得的微量营养素、可食率、生熟状态与换算关系、过敏原、储存建议、来源/版本、参考价格（可选）。

区分生、熟、带皮、去皮等食材状态；单位转换需可追溯。未知值不能默认为零；不编造营养数据或生熟换算。价格只是估算，不伪装为实时市场价格。数据质量不足时报告真实数量和缺项。

## 九、菜谱数据库

初期目标100道以上实用菜谱，后续扩展至500道以上。真实可做、数据可靠、步骤完整优先，不为凑数编造。覆盖早中晚餐、加餐、蛋白质菜、蔬菜、主食、汤类，优先中国家庭常见、采购容易、操作简单的菜品。

例如葱姜蒸鸡胸肉、清蒸鲈鱼、清蒸三文鱼、番茄牛肉汤、虾仁豆腐汤、菠菜豆腐汤、黑胡椒鸡腿肉、水煮西兰花、蒸红薯、杂粮饭、豆浆燕麦、水煮蛋、酸奶坚果水果碗。

字段：唯一 ID、菜名、分类、适用餐次、食材 ID 与克数、生熟重量、调味料用量、所需厨具、制作步骤、备料/烹饪/总时间、难度、营养成分、过敏原、可替换食材、允许调整份量范围、是否适合备餐、冷藏冷冻建议、解冻复热方法、菜系、口味标签。

营养值从食材库和用量计算，避免手填互相矛盾的数字。调味料、植物油也纳入计算。替换食材和调整份量应同步更新营养、过敏信息、制作说明。

## 十、随机一周食谱算法（核心功能）

禁止完全无约束随机抽取。顺序如下：
1. 读取最新档案与体重，计算营养目标。
2. 排除过敏、明确忌口及不适合安全条件的菜谱和调味料。
3. 依据厨具、制作时间、预算和饮食偏好筛选。
4. 随机组合7天三餐与可选加餐。
5. 在允许范围内优化食材份量。
6. 校验每日及每周营养、食材多样性、菜品重复、成本和备餐可行性。
7. 生成最终食谱、采购清单及备餐计划。

默认周一到周日，每天热量尽量在目标值上下5%之内，并同时满足必要蛋白质、脂肪和营养安全条件；无解时提示具体原因，不伪造成功。避免极端食谱和不合理份量。

支持固定早餐、随机午晚餐，指定菜品必须出现，合理复用食材避免浪费，尽量避免连续多日完全重复。支持随机种子及复现；在设备存储与性能允许范围内不限重新生成次数、无付费 API。

过敏、明确忌口、安全条件及硬性厨具限制永不自动放宽。设最大尝试次数及失败原因；仅允许用户主动调整非安全限制。不能满足安全要求时停止生成。

## 十一、食谱展示及调整

周一至周日快速切换。展示每日总热量、蛋白质/碳水/脂肪/纤维、各餐菜品、食材重量、制作时间、每餐营养信息；菜谱详情展示做法、调味料、设备、过敏原、替换及储存方式。

支持换一道菜、换一餐、换一天、重生成整周、锁定菜品、收藏、屏蔽、手动调整食材克数、保存、复制、分享。

每次更换或调整后重新校验营养和限制条件，并刷新采购及备餐计划。禁止只改菜名而不改数据。若修改不满足安全要求，应拒绝或提示修正，而非标记合格。

## 十二、采购清单

按肉类、鱼虾、蛋、豆制品、蔬菜、水果、主食、乳制品、坚果、调味料汇总。展示名称、全周需求量、建议采购量、统一单位、参考价格、已购买状态、家中库存。

自动合并同类食材，正确处理生熟重量、可食率、包装规格和用餐人数；注意单人营养值与多人采购量分开计算。

支持勾选、进度、库存扣除、复制和分享、一次采购或分两次采购、每次费用估算。修改食谱同步重算采购清单，并合理保留已经勾选的记录（数量增加时提示补买）。缺失价格标未知，不将其视为免费。

## 十三、集中备餐计划

模式：周末一次备餐、每隔2～3天、每天现做、混合模式。

结合厨具、冰箱/冷冻室、时间和实际食材，自动安排采购日期、清洗、肉类分装、主食集中制作、单餐份量、腌制、冷藏冷冻、解冻复热、每天烹饪顺序及预计时间。

食物安全是硬性要求，不建议将全部熟食冷藏七天。依据权威食品安全资料记录来源，按食材种类提供安全储存、冷却、复热方法；生熟分离。无冰箱或冷冻室时自动调整采购和备餐频率，无法安全执行时给出提示。

## 十四、体重记录及动态调整

支持每天或每周记录体重，选填腰围，允许修改/删除错误记录。展示初始/最新/目标体重、累计变化、近7天均值、近30天趋势、历史曲线。记录不足时如实显示，不插入虚构数据。

提供一般生活方式建议；不能因一天不下降就减少热量，不能因短期波动提示失败。生成下一周时自动读取最新档案，依据合理规则更新营养需求。旧方案不变。

## 十五、历史方案管理

每个方案保存名称、创建日期、日期范围、生成时体重和档案快照、营养目标、完整7天食谱、食材重量、制作方法、采购清单、备餐计划、菜谱与算法版本、随机种子。

支持查看、改名、复制、收藏、删除、重新使用、导出及分享单份方案。

历史快照独立保存；后续修改体重、档案、偏好、菜谱库不得改变旧方案。重新使用旧方案时应提示它是否仍符合当前安全限制，避免将旧方案自动标记为当前适用。

## 十六、多人使用与隐私

所有用户无须注册，访问同一网址。各自设备和浏览器独立存储身体档案、健康注意事项、偏好、历史方案、体重记录、采购记录、收藏和库存；使用 IndexedDB 或可靠本地存储。

默认无跨设备同步，同一设备同一浏览器的数据不等于不同账号隔离。清除站点数据、隐私浏览、更换手机、卸载应用或浏览器清理可能丢失记录；明确提示定期备份。

提供完整个人数据 JSON 导出、导入恢复、删除全部数据（二次确认）、版本升级、损坏及存储失败处理；导入时校验格式、版本和字段，不执行其中的代码。建议提供合并/覆盖提示。

分享单份食谱或采购清单时默认不包含姓名、年龄、身高、体重、疾病信息或健康档案；可采用文本或可导入的食谱文件。个人健康信息禁止写入公开仓库、日志、测试数据和外部分析服务。第一版不需要云服务，预留未来登录及同步接口。提供清晰的隐私说明、健康免责声明。

## 十八、自动化测试与验收

实际编写并执行测试，至少覆盖：
1. 首次打开填写档案。
2. 不同身体数据得到不同营养目标。
3. 成功生成完整7天食谱。
4. 多次生成不同且合格的组合，同一随机种子可复现。
5. 食谱营养与食材数据库计算一致。
6. 只有蒸锅和煮锅时，不出现需要其他厨具的菜谱。
7. 排除过敏及明确忌口，包括调味料中的潜在过敏原。
8. 换菜后营养、采购及备餐同步更新。
9. 采购量与全周食材量、换算和人数一致。
10. 更新体重生成新食谱。
11. 修改个人资料不改变历史方案。
12. 关闭并重新打开后，历史数据仍存在。
13. 不同浏览器环境数据独立。
14. 导出、重新导入恢复。
15. 离线查看及生成食谱。
16. 手机屏幕没有横向溢出。
17. 按钮均有真实功能。
18. 不合理、缺失或极端输入有正确提示。
19. 无法满足限制时安全停止，不无限循环。
20. 低体重及医学营养高风险用户正确拦截和提示。
21. 支持的手机浏览器可安装 PWA。
