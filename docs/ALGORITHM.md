# 七天食谱算法

1. 读取档案、最新体重和分餐偏好。健康筛查、过敏、强制忌口、屏蔽、设备、预算和食品限制先过滤。用户填写的本餐不喜欢食材只对该餐排除。
2. 先选餐次模板与食材槽，再从合法标签中选菜。早餐主食配早餐蛋白，可加奶类、豆浆、坚果或水果。午餐为主食、蛋白质和蔬菜，可配清汤。晚餐使用主食、蛋白质与蔬菜或清汤。加餐只使用整果或合适的乳品、豆浆和坚果。三餐时把计划水果放到早餐，四餐时放到加餐，两餐时放到早午餐。带有明确用法的夹馅只与全麦面包搭配，鸡丝燕麦只与燕麦粥搭配，同餐最多一份汤类。
3. 用固定种子的随机序列挑选候选。早餐优先采用人工编辑的真实搭配。固定早餐、指定菜和锁定槽先约束候选。独立分餐可固定主食、主菜和配菜，保留水果及克数的调整空间。未单独修改的午晚餐沿用档案时长，早餐默认上限为 10 分钟。三餐加餐的目标为 25%、35%、30%、10%，主餐允许上下 8.5 个百分点，加餐允许上下 4.5 个百分点。三餐为 27%、38%、35%，两餐为 48%、52%。
4. 先按餐次调整主食，再调整蛋白与加餐，水果根据当天目标单独调整。保留热量、蛋白、脂肪、碳水、纤维、钠、蔬果量和用时校验。已知钙不能超过 2000 毫克。合格候选继续按钙、钾、维生素 C 参考差距、能量分配、重复、口味、烹饪便利、食材偏好和果蔬多样性排序。每天最多抽样 2400 次，最多比较 12 个合格候选。
5. 验证全周多样性、成本、固定搭配和重复限制。页面展示每日及全周日均营养参考校验，微量营养缺值单独标注。钙、钾和维生素 C 的低值会提示并降低排序，特别严格的档案仍可能低于参考。超时或无解时指出餐次或冲突因素。
6. 换单项时保持餐次、槽位、其他菜与克数。换餐或换日仍须满足搭配与用时。每次变更均校验全周并从食材与克数重新汇总采购和备餐。原来保存的历史快照保留原内容和版本。

相同输入和算法版本使用同一随机种子可复现菜品与份量。创建时间、起始日期和方案 ID 依运行环境而定。时间从已有食材开始估算，熟制食材需在采购或安全备餐中提前取得。

## 1.2.0 同餐去重与烹饪模式

`food-semantics.ts` 将食材数据库记录合并到稳定语义 ID，保留生熟记录、食材别名、食物大类、细分类别和营养角色。菜谱依餐次标签、槽位与食材用量识别核心食材。不同酸奶、生熟鸡蛋、生熟鸡胸等可触发同餐互斥，调味小料、复合菜内部食材及少量夹馅保持可用。合法候选再根据食材重叠、口味与全周复用计分。采购仍以真实配方的食材记录和克数汇总，避免混算生重、熟重或不同包装。冷藏与开封保质期仍按产品标签和备餐建议处理。

`cooking-profile.ts` 按单日单餐覆盖、常规餐次覆盖、本次生成的临时模式、全局档案的顺序解析设置。混合模式有工作日、周末默认，默认全局为简单。所有模式都遵守用户的最长总用时、主动时间和最大菜品数，以及厨具、营养和食品安全约束。模式所列分钟段是排序目标。极简另限制复杂度。早餐未自定义时继承原 10 分钟上限。

`cooking.ts` 综合主动操作、切配、调味、步骤、厨具及清洁负担估计复杂度。等待与主动时间分算。允许备餐而且有冰箱时，标明可复热的菜在需要时用前一日制作与当日复热安排。复热仍需要所用厨具，需将熟食中心加热到 74°C。用时从实际备齐食材开始估算，提前制作时间单列。

先检查健康和食材限制、选餐次模板与角色，再检查语义重复与搭配。份量优化后，全周再次校验营养、餐次、复杂度与用时、多样性、指定菜和采购预算。快捷操作保留当前规则。简单一点会降低操作负担，丰富一点会增加菜品数或工序，减少一道菜会恰好少一项，一锅料理要求只用一个加热容器完成主餐。更换同类食材在同槽位内重选共同核心类别的配方。找不到替换时原方案保持有效。


## V2 周食材池

以标准食材 ID 统一生熟和别名计数，具体采购仍按实际商品 ID 区分毛净、包装和价格。自动候选权衡菜谱覆盖、参考单价、已确认库存和上周使用情况。固定早餐与必选菜先登记所需食材。严格手动模式对允许集合外食材报错。用户指定的用量参与候选评分，适用的份量和营养边界始终生效。

同一随机种子在有限候选和搜索次数内复现。保留食材重生成时优先使用上周实际食材，另尝试已有候选集合。换菜优先使用本周集合，允许补充时才尝试池外食材。确认之前保持原计划。每个候选都需通过同餐语义、食用时间、设备、每日能量、宏量及钠和纤维约束。热量优化目标为 ±5%。其他微量营养低于参考值时给出显式提醒，缺失指标保留未知。


## V2.1 的生成约束

先计算起始日、预定购物日期和实际采购 ID，再筛周食材池和餐次模板。生熟变体共用采购 ID，营养及语义去重使用原始食材数据。子路径共用最终校验和派生采购。食品安全提示用于实际保存与备餐，既定购物日保持不变。换菜保持现有起始日。

旧总制作、主动、等待分钟数以及菜品数量限制仍可从旧备份读取，生成与评分已移除对这些字段的依赖。简单和家常只按切配、步骤、调味和工具等排序。不限制时按菜谱搭配、营养和食材偏好排序。烹饪设备和自制准备设备必须真实可用。制作与复热耗时保留在菜谱详情和备餐排程。

## V2.2 库存偏好

周食材池读取独立库存账本的实际余额，并按标准采购商品汇总。库存复用用于选择和排序，继续执行餐次、营养、厨具、过敏和用户排除条件。没有库存时沿用原候选规则。采购计算按食用日与既定购物日期分配实际余额，同一份余额只预估抵扣一次。配餐和换菜遵循 V2.1 的无烹饪时间限制规则。

## V2.3 已执行任务与实用份量

新方案有独立任务范围。任务键还包含用餐日期、餐次、菜谱、该餐位置，以及份量和采购换算指纹。实际执行后保留原签名和操作食材，按真实扣减的原材料重量核算。旧版在用方案继续识别原任务键。历史方案重新启用时使用新的任务范围。

换菜、整餐、整天和手动克数入口校验执行状态。重生成保留执行过的餐次与已过日期，只求解仍可调整的餐次。旧餐次与新配置无法同时满足时保留原方案并返回校验原因。

单人少量种类按相同实际采购 ID 统计肉、菜、主食、果、蛋奶豆和坚果，优先复用原料与账面库存。基础食材先使用小候选池，再按需放宽。约 13～17 种是偏好目标。肉类、主食、蔬菜和整果在配方允许时按 5 克取整，整蛋优先按约 50 克可食份计，配方边界过窄及小剂量调味保留所需精度。使用取整后的重量重新计算营养、采购和分装。烹饪时间继续仅用于显示。

## V2.3.1 全品类采购与复用

保留营养食材、采购商品和替代做法三套独立概念。候选先检查过敏忌口、厨具、严格指定和锁定，再在选定原材料池内配餐。少量种类、均衡搭配、丰富多样都可比较至多两份已通过校验的整周方案，按实际补买种类、一次性需求、价格、库存抵扣和包装结余评分。持有库存直接参与不同类别候选排序。

自动变体只迁移受限用途内的同类调味，并且重新核对营养、购备餐和预算。条件相容的肉类、鱼类、豆制品、谷物等通过各自经过审核的菜谱转换。调味、排序和校验均不依赖制作耗时。已执行日期及锁定菜品沿用原任务和食材。[审查列表](SUBSTITUTIONS.md)


## V2.4 替换和固定水果

替换以实际核心食材集合判断。换做法保留核心集合，等价取料变体与普通菜谱都在复核范围。选择器先按库存与本周使用情况分组，保存前验证档案、餐次、去重、营养、预算、采购日、食材池与任务锁定。对于候选补购，使用最终重算的采购确认。用户显式选多个品种时，上调当周非严格池的对应品种额度。

固定水果在候选预选和餐次分配时生效。单日例外绑定日期。切换整周时仅更改尚未执行且未锁定的水果餐位，保留其他菜品和实际流水。复合菜使用不同水果时提示先调整该菜品。紧预算的丰富模式可尝试集中采购候选，购物批次与营养阈值照常检查。
