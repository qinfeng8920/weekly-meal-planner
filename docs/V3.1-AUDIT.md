# 天天减 V3.1 专项审查记录

基线为正式 V3.0.0，主分支提交 `86e084e`。本次实现和验收以 [最终合并需求](PRD-V3.1.md) 为准。以下区分了在旧代码确认的问题以及原行为在回归中继续成立的项目。

| 章节 | 旧版复现、根因或核对结果 | V3.1 改动及回归 |
| --- | --- | --- |
| 1–3 | 用男性 25 岁、173 厘米、久坐、目标 60 千克，分别输入 72 和 71 千克。旧版 BMI 分别为 24.0569 和 23.7228，目标 1718 和 2006。旧代码把 BMI 24 用作缺口开关。 | `nutrition.ts` 对主动减脂比例线性衰减，示例改为 1718 和 1721。系统推荐在 BMI 24～25 渐进启用，兼顾正常 BMI 默认维持与边界连续。测试未舍入值和上下限。 |
| 4–5 | 旧档案只有速度选项，首页缺少计算依据。趋势的窗口以最后一条称重为锚点，陈旧数据仍可能触发。 | `ProfileForm.tsx` 增加明确偏好和适用确认。`weight.ts` 统一当地日历日期，用近期样本和最新值分别计算与保护。`Dashboard.tsx` 显示实际模式、计算日期、原因和具体上限。法规依据与应用规则见 [营养计算](NUTRITION.md)。 |
| 6 | 生成后录入一次普通称重，旧 `stale` 停止编辑并在后续生成时丢弃菜品锁。 | `main.tsx` 区分建议变化与安全重校验。普通换菜、调整仍按原方案目标验证。更新未执行部分采用新目标，执行部分与锁定保留，有冲突时提示食物名称。 |
| 7–8 | 在档案改首填体重会重设进度基数。有实际记录时改档案不会更新当前值。同日编辑或新增会静默覆盖原记录。 | 首填基数独立保存，主动重开阶段需确认。存在称重记录时由称重唯一更新当前值。日期冲突直接提示，未来或非法日期不录入。分别验证反弹、零分母、删除最近值及跨年。 |
| 9–10 | 首页和采购页分别算分母，旧采购状态用价格完整度推断部分购买。 | `plan-progress.ts` 共享商品和批次派生。未知价格与数量待核对独立，真实库存覆盖单列。跨批同商品计为多项、同一待买商品只计一种。 |
| 11 | 历史重估重新读取现价、现用换算，并重新构造旧周购物预估。核对后确认实际支付本已按交易日期进入对应周，计划外费用已有支持。 | `logistics.ts` 按历史批次及原重量重估计划参考金额，保留原实付、未填实付估算和原备餐。新记账的未付参考额单独保存。对旧收据中没有成交参考价的记录，当前统计沿用可得的参考价。 |
| 12 | 入库、扣减、撤销、清空及账本同源已实现。原测试验证同日累计、实际取用、清空及备份往返。 | 继续使用 `inventory.ts` 的账本和原子写入。补验撤销分阶段及清空后需买项目变化。 |
| 13 | 首页按制作标记找备餐，采购页按取用标记找，同一批可能不一致。撤销取用会顺带撤销制作及用餐。 | 共享下一批与四个阶段，逾期未处理有文字提示。取用撤销前需先撤销依赖它的制作或用餐，保留独立分装标记。 |
| 14–15 | 宏量和钙、钾、钠、纤维及维 C 有来源或缺失状态。额外微量数据原先仅在原材料详情展示。用餐状态并无实际摄入克数。 | 共用原有铁、镁、锌、叶酸、B12 成分与缺失数据，日、周显示用料覆盖。调味料仍按独立商品及真实成分，缺失时保持未知。食谱标明计划量，完成餐次与库存取用单独统计。 |
| 16–17 | 个人目标与多人采购，包装、毛净、生熟换算，多食材锁、固定搭配及换食材去重已有回归。 | 继续使用标准采购 ID 和已确认换算。现价包装或体积系数未知时标为数量待核对。缺少可验证密度的液体保留重量口径。确认非历史数据的真实余额参与筛选。 |
| 18–19 | 历史详情沿用了当前任务；旧版部分档案没有执行记录。 | 新历史明确保存本方案任务和集中制作标记，旧档案显示历史状态未知。自定义起始日支持未来有效日期，跨午夜按本地日期刷新。更新当前方案沿用同一周。 |
| 20 | 跨标签页用 IndexedDB 比较并写入，Worker 使用输入快照，已有取消和防止覆盖逻辑。 | 保留原事务及冲突保护，Worker 前重新评估档案，写入时仍校验完整快照。显式导入备份核对未来称重日期，普通升级保留旧字段。 |
| 21–22 | 从旧版实际保存档案、体重、价格、执行、实付和历史。 | 以前后生产构建同源验证 IndexedDB 字段一致和离线升级。以相同安全阈值运行自动化测试。正式发布记录见 [部署](DEPLOYMENT.md)。 |

食材个别微量指标和液体密度仍取决于数据来源及产品标签。云端验收覆盖浏览器和移动视口，实体手机系统安装与网络表现另需真机核对。
